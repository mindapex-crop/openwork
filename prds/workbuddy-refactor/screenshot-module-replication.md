## 一、逐模块：界面原貌 + 现状 + 复刻方案

### M1 主界面 / 三栏工作台（`screenshot-20260826-233219.png`）

**WorkBuddy 界面原貌**：三栏布局。
- 左：侧边栏 = 新建任务 + 导航（助理/项目/专家/自动化/资料库…）+ 任务列表（按文件夹分组，任务卡=标题+状态+最近更新时间）+ 底部头像。
- 中：对话区 = 任务标题栏（顶部 4 操作：对话内搜索/分享/历史提问/详情面板）+ 消息流 + 底部新建任务栏（Ask/Craft/Plan 分段 + 模型 + 工作空间 + 技能 + 连接器 + 权限 + 附件 + 发送/停止）。
- 右：结果区四视图（产物/全部文件/变更/预览），无对话时不可展开。

**OpenWork 现状**：三栏已具备（`app-sidebar.tsx` + `session-surface.tsx` + `side-panel.tsx`）；Ask/Craft/Plan 已实现；右侧四视图已有产物/文件/变更，浏览器视图存在。

**复刻方案（P1）**：
1. 对话区顶部补齐 4 操作：对话内搜索（`find-bar.tsx` 已存在，接入口）、任务分享（`session-share.ts` 已存在，接入口）、历史提问、详情面板开关。
2. 任务状态 6 态（进行中/已完成/失败/待处理/规划中/已归档）+ 状态/日期筛选面板 + 重置。
3. 右侧「预览」视图补地址栏 + 刷新入口。
4. 输入区补连接器快捷管理入口（plug 菜单 → 连接器直达）。

### M2 新建任务页（`新建任务页.png` / `新建任务页1.png`）

**WorkBuddy 界面原貌**：底部新建任务栏从上到下：工作模式三档（问一问/做一做/想一想）→ 模型名（常驻，`Auto ▾`）→ 输入框（`@` 引用、粘贴截图、上传/拖拽）→ 左下角工作空间控件 → 发送按钮（执行中变停止 ■）。

**OpenWork 现状**：`composer.tsx` + `new-task-composer.tsx` 已实现三档模式、模型选择、工作空间选择器、附件、语音、停止/重新生成。会话空态 hero 已有。

**复刻方案（P1）**：输入区补连接器快捷入口（`connect-capability-inventory.ts` 接 plug 菜单）；对齐三档中文文案（问一问/做一做/想一想 → `task-mode.ts`）。

### M3 技能（`技能.png`）

**WorkBuddy 界面原貌**：技能市场 + 已安装两区；添加技能 3 种（上传/查找/创建）；随时开关；批量卸载；安全提示（提示词注入/越权/后门风险）。

**OpenWork 现状**：`skill-marketplace-page.tsx` 已有分类筛选（全部 16/写作 4/数据分析 3/编程 3/办公 3/研究…）、斜杠命令调用说明。

**复刻方案（P2）**：补「已安装」与「市场」分区切换；补开关/批量卸载/安全提示横幅。

### M4 灵感（`灵感.png`）

**WorkBuddy 界面原貌**：精选内容陈列，查看/收藏（红心）/做同款（自动预填 Prompt + 加载 Skill/专家配置）；七大场景分类 + 搜索；浏览不耗积分。

**OpenWork 现状**：`inspiration-page.tsx` 已有精选组合包（周报助手/代码审查专家等）、工作流标签、应用能力。已验证 `onApplyToSession` 可一键应用。

**复刻方案（P2）**：补收藏（红心，persist 到 localStorage）+ 收藏筛选；补「做同款」= 现有「应用到会话」+ 预填技能/专家。

### M5 自动化列表 + M6 自动化创建（`自动化.png` / `自动化-创建页.png`）

**WorkBuddy 界面原貌**：
- 列表页：定时任务列表（名称/工作空间/提示词/模型技能/定时规则/推送到小程序）+ 历史执行记录；右上角「添加」表单弹窗；任务卡「···」菜单（编辑/测试运行/暂停恢复/删除）。
- 创建页：支持表单创建与**对话创建**（自然语言解析）；模板（新闻推送/周报生成/体检预约/学习计划）。

**OpenWork 现状**：`automations-page.tsx` 已有列表 + `automation-editor.tsx` 表单 + 模板卡片（`automation-templates.ts`）；Den 登录后才可用自动化调度。

**复刻方案（P2）**：核对任务卡「···」菜单完整度（编辑/测试运行/暂停恢复/删除）；补对话式创建入口（复用专家对话 → 解析生成表单）。

### M7 连接器（`连接器.png`）

**WorkBuddy 界面原貌**：MCP+CLI / Skill+CLI 形态服务卡片列表：卡片名 + 绿色连接圆点 + 启用/禁用开关 + 「+」添加；自定义连接器安装 MCP；解绑为弹窗。

**OpenWork 现状**：`connectors-view.tsx`（设置内）+ `/connectors` 独立页（SettingsSurface embedded）。已验证独立页正常渲染。

**复刻方案（P1）**：核对独立页卡片形态（服务名 + 绿点 + 开关 + 添加 + 解绑弹窗）；确认从 `/connectors` 可直接管理而非仅设置内。

### M8 资料库（`资料库.png`）

**WorkBuddy 界面原貌**：「我的文档」/「团队空间」两分区 + 一棵目录树；MD/CSV/HTML 三载体互相引用联动；文档/空间「···」菜单（添加到任务/重命名/复制链接/邀请和管理成员）；AI 修改可审阅可回退。

**OpenWork 现状**：`library-page.tsx` 已有 文件/知识/记忆 三 tab（快照验证已显示）；`knowledge-page.tsx` 存在但已知 localStorage 假持久化（半成品）。

**复刻方案（P2）**：补「我的文档/团队空间」分区与目录树；修 knowledge 域 localStorage 假持久化 → 迁移到 server 持久化（对齐 experts 的 SQLite 方案）。

### M9-M11 专家 / 专家应用 / 专家详情（三张专家截图）

**WorkBuddy 界面原貌**：
- 专家列表：卡片网格，卡片=能力介绍/擅长领域/任务示例；点击「召唤专家」进入对话。
- 专家应用：以 App 形态呈现的专家（区别于角色专家），可一键启用。
- 专家详情：弹窗/面板展示人设+方法论+工具链（技能/模型），CTA「召唤专家」。
- 专家团：团长自动拆解 → 并行执行 → 整合交付（积分约为单专家 3-5 倍）。

**OpenWork 现状**：`experts-page.tsx` 已有卡片网格 + 搜索 + 新建 + 详情面板（`expert-detail-panel.tsx`，含编辑/删除）+ 专家组 tab（`expert-group-*`）+ 一键运行（`expert-group-runner.ts` → `/teams/run-simple`）。CRUD 走 `/api/experts`（server SQLite，本次已修好跨源 fetch）。

**复刻方案（P1）**：核对专家卡片三要素（能力介绍/擅长领域/任务示例）与详情 CTA「召唤专家」；验证专家组一键运行端到端（`/teams/run-simple` 已确认注册，需实测长耗时响应）。

### M13-M17 项目 / 任务 / 动态 / 计划 / 资产（5 张项目截图）

**WorkBuddy 界面原貌**：
- 项目列表：项目卡（名称/描述/进度/成员）；「新建项目」。
- 项目详情四 tab：**任务**（对话+工作空间，任务卡状态流转）、**动态**（三类：与我有关/成员动态/自动化）、**计划**（计划列表/甘特）、**资产**（统一文件管理，默认 5GB，工具栏实时显示已用/总量）。
- 项目 = 聚合指令/连接器/专家/技能/资料；邀请成员→复制链接→管理员审批；任务流转打包产物+进度摘要+自定义字段。

**OpenWork 现状**：`projects-page.tsx` 项目卡 + `project-detail-panel.tsx`（任务看板 + 计划分列 + 证据/子任务/assignee + 拖拽）。**缺**：动态时间线、资产文件管理+容量、计划独立视图、邀请成员审批。

**复刻方案（P1）**：
1. 项目详情顶部加四 tab 切换（任务/动态/计划/资产）。
2. 动态 = 从 project-store 的 task 变更事件派生时间线（或新增 activity 数组）。
3. 资产 = 复用 server `listWorkspaceCatalog`/`workspace-files-panel.tsx` 的文件树能力 + 容量显示。
4. 邀请成员 = 复用 `share-workspace-modal.tsx`（已有分享访问面板）。

## 二、本次已修复的问题（闪屏/路由/数据加载）

1. **闪屏根因**（`use-workspace-route-state.ts`）：`standaloneRouteActive` 正则漏掉 `experts|inspiration|library|connectors|plans`，点击后 normalize 副作用把用户拽回 `/workspace/:id/session`。已补全正则 → 8 个 tab 全部端到端验证通过，URL 稳定。
2. **专家页数据加载失败**：专家 store 硬编码相对路径 `/api/experts`，headless-web 下打到 Vite（5178）返回 SPA HTML。新增 `resolveServerApiBaseUrl()`（openwork-connection.ts），修复 `experts-store.ts` / `expert-group-runner.ts` / `agent-management-view.tsx` 三处（后者同时把 `/api/agents` 改为 server 实际注册的 `/agents`）。
3. **experts-page.tsx JSX 标签不闭合**：已在上一轮修复，typecheck 通过。

## 五、验证方式（沿用仓库规范）

- 每个模块改动后：`pnpm typecheck` → 浏览器端到端点击验证（无闪屏、URL 稳定、数据真实加载）→ 需要时补 testkit spec（`evals/specs/**/*.test.ts`）。
- 验收证据：截图为主、执行日志为辅。
